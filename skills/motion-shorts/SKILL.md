# 모션그래픽 쇼츠

소재를 받아 **새로 디자인한** 9:16 모션그래픽 쇼츠를 만든다. 결과물의 품질은 네 가지가 결정한다.

1. **정확성**: 화면 글자·자막·나레이션은 소재에 있는 사실만 담는다.
2. **동기화**: 지금 말하는 단어가 화면에서 움직인다. 고정 초 단위로 맞추지 않는다.
3. **가독성**: 겹침이나 잘림이 없고, 자막·쇼츠 UI가 내용을 가리지 않는다.
4. **리듬**: 첫 프레임부터 내용이 보이고, 무음 구간이 없고, 끝이 처음으로 이어진다.

아래 절차는 이 네 가지를 지키기 위한 것이다.

`$SK` = 이 스킬 폴더, `$W` = 작업 폴더(세션 스크래치패드 아래, 예: `$SCRATCH/ms_<주제>/`).
엔진 API와 디자인 레시피는 `references/scene-cookbook.md`에, 음성·받아쓰기 세부 사항은 `references/voice-pipeline.md`에, 업로드 메타데이터와 CTA는 `references/youtube-cta.md`에 있다. 해당 단계에 이르면 읽는다.

## 0. 환경 확인 (1분)

```bash
which ffmpeg node python3 && python3 -c "import numpy" && node -e "require('playwright')" 2>/dev/null || ls /opt/node22/lib/node_modules/playwright
```
폰트는 `assets/fonts`(Pretendard)에 들어 있다. 외부 CDN이 막힌 환경이 많으니 웹폰트를 내려받으려 하지 않는다.

## 1. 소재 읽기 → 구성 설계

PDF는 `pdftotext -layout`으로 읽고, 만화·이미지 PDF는 `pdftoppm -r 80`으로 페이지 이미지를 만들어 Read로 본다.

구성 원칙:
- **장면 10~12개, 나레이션 450~600자**. 이 분량이면 1.15배속 기준 75~95초가 나온다. 3분 안이면 쇼츠로 인정되지만, 짧고 촘촘할수록 끝까지 보는 비율이 높다.
- **구조**: 훅(질문이나 핵심 결론) → 항목·사례 전개 → 실무 시사점 → 맺음(CTA).
  - 나열형 소재(법 개정 n가지, 체크리스트)는 "핵심 n가지" 구조로 만들고, 상단 진행 칩(`CONFIG.items`)을 쓴다.
  - 이야기형 소재(만화, 사례)는 장면 흐름대로 가고, 캐릭터를 쓴다.
- **테마 선택**:
  - `dark`(안전 표지풍 인포그래픽): 법령·정책·뉴스
  - `paper`(따뜻한 종이색과 캐릭터): 사례·만화·스토리

## 2. 대본 작성 → 사용자 승인 (생략 금지)

음성 생성에는 크레딧이 들고, 대본이 바뀌면 다시 생성해야 한다. 그래서 반드시 먼저 보여주고 승인받는다.

작성 규칙:
- **원문에 충실하게.** 소재에 없는 사실·수치·평가를 넣지 않는다. 채널 관점의 실무 조언(예: "절차부터 점검해 두시기 바랍니다")을 넣었다면, 승인 요청 때 "소재에 없는 부분"으로 짚는다.
- **TTS가 틀리기 쉬운 표기는 한글로 쓴다.** `5%`→`오 퍼센트`, `3명`→`세 명`, `1심`→`일심`, `1년`→`일 년`. 화면에는 숫자로 크게 보여준다.
- **장면당 한두 문장.** 화면 글자를 그대로 읽지 않고 흐름을 잇는다. 숫자·조문·출처·연락처는 화면에만 둔다.
- **맺음말은 기본적으로 읽지 않는다.** 마무리 인사는 '여기서 끝'이라는 신호가 되어 넘김과 루프 효과를 해친다. 그래서 대사는 실무 시사점에서 끝내고, 마지막 장면은 나레이션 없는 장면(손 인사, 브랜드, 질문 카드)으로 둔다. 사용자가 원하면 `상생의 노동법, 박재우 변호사였습니다.`를 읽는다. "구독·좋아요"는 사용자가 원할 때만 넣는다.
- 소재가 시행일 등을 확정하지 않았으면(예: 공포일 미정) 확정된 것처럼 쓰지 않는다.

승인 요청 형식:
- 장면별로 `**S1 — 제목**`과 인용 블록 대본을 쓴다.
- 그 아래에 (a) 읽지 않고 화면에만 두는 것, (b) 소재에 없거나 추정한 부분, (c) 13초를 넘는 긴 장면, (d) 예상 길이를 짚는다.

승인되면 `$W/script.json`(장면별 문자열 배열)에 저장한다.

## 3. 프로젝트 만들기 + 장면 제작 (음성 생성과 병렬)

```bash
python3 $SK/scripts/new_project.py $W --theme dark --script $W/script.json
```
`index.html`(엔진), `fonts/`, 임시 `timing.js`가 생긴다. 임시 타이밍은 초당 8음절로 추정한 값이고, 실측과 2% 안팎으로 맞았다. 그래서 음성을 기다리지 않고 장면을 먼저 만들 수 있다. 실제 타이밍으로 바꿔도 장면 코드는 단어 기준이라 고칠 필요가 없다.

`index.html`에서 수정할 곳:
- `CONFIG`: 테마, 시리즈 제목, 항목 수, 브랜드
- **SCENES 구역**: 장면 배열 `S`, 자막 줄바꿈 `CAPS`, 전환 `TRANS`, 원형 전환 중심 `IRIS`

나머지 엔진 코드는 건드리지 않는다. 데모 장면 3개를 지우고 실제 장면을 쓴다. 장면 작성법·헬퍼 목록·레이아웃 좌표·연출 레시피는 `references/scene-cookbook.md`를 읽고 따른다.

핵심 규칙(이유 포함):
- **모든 등장 시점은 `e.w('단어')`로 잡는다.** 고정 초를 쓰면 실제 음성과 어긋난다. 같은 단어가 두 번 나오면 `e.w('두',1)`처럼 몇 번째인지 지정한다. 첫 글자만 같은 다른 단어("확인"과 "확인된" 등)가 앞에 있으면 엉뚱한 단어에 걸리니, 더 긴 접두어를 쓴다.
- **첫 프레임에 이미 제목이 보이게 한다.** 등장 시작을 음수(`P(t,-.2,.1)`)로 둔다. 쇼츠는 첫 1초에 넘길지가 정해진다.
- **효과음은 장면마다 `sfx(e)`로 선언한다.** 화면 동작과 같은 단어 시점에 둔다. 장면 전환 소리는 자동으로 붙는다.
- **자막 줄바꿈은 의미 단위로 직접 지정한다(`CAPS`).** 한 음절 단어(데·수·등)로 줄을 시작하지 않는다.
  - 화면 글자가 나레이션과 똑같은 장면(훅 문장, 맺음)은 `noCap:true`로 자막을 끈다.
- **긍정적인 몸짓만 쓴다.** 캐릭터 손은 손바닥을 편 모양이다(주먹과 엄지는 '엄지 내리기'로 읽혔다). 표정과 몸짓이 내용과 맞는지 본다.

## 4. 나레이션 생성 + 받아쓰기 (ElevenLabs)

세부 사항과 함정은 `references/voice-pipeline.md`에 있다. 요약:
1. `creative_create_flow`로 플로우를 하나 만든다.
2. 가장 긴 장면으로 `estimate_only` 비용을 확인하고 한 줄로 알린다.
3. 장면마다 `creative_generate_speech`를 호출한다.
   - voice `tR2KSgzWczYwLUo9Suqn`(박재우 변호사(1)), model `eleven_v4`, **`generations_count:1`**
   - 같은 flow_id로 한 턴에 모두 호출한다.
4. 상태가 완료되면 각 음성 노드(`node_id`)를 `connect_from`으로 넘겨 `creative_transcribe_audio`(eleven_scribe_v1)를 장면마다 호출한다.
   - 파일 업로드는 googleapis가 막혀 실패하니 쓰지 않는다. 받아쓰기는 0크레딧이었다.
5. 받아쓰기 세션 전체로 `creative_get_flow_run_status`를 한 번 호출한다. 결과가 길면 파일로 저장된다. 그 파일 경로를 쓴다.
6. 음성 파일을 정리하고 실제 타이밍을 만든다.
   ```bash
   python3 $SK/scripts/prep_audio.py --status <status파일> --script $W/script.json --out $W
   ```
   - 장면마다 MATCH/DIFF가 나온다. 전부 MATCH면 받아쓰기 결과가 대본과 글자까지 같다는 뜻이라, 숫자 발음까지 검증된 셈이다. DIFF가 있으면 해당 장면을 들어보고, 필요하면 그 장면만 다시 생성한다.
   - 이 과정에서 앞뒤 무음을 자르고, 1.15배속으로 바꾸고, `timing.js`를 실제 값으로 덮어쓴다.
- 받아쓰기 결과의 `source.url`은 2시간 뒤 만료되니 바로 실행한다.

## 5. 스틸 검수 → 렌더링

```bash
node $SK/scripts/render.js $W/index.html meta  $W/meta.json            # 전체 길이·큐·효과음 목록. 페이지 오류가 있으면 출력됨
node $SK/scripts/render.js $W/index.html sheet $W/sheet.jpg 0 6.2 14.6 ...   # 각 장면 끝 무렵 + 전환 중간 시점
```
시트를 Read로 보고 아래를 확인한다. 고칠 게 있으면 고쳐서 다시 본다. 렌더링은 90초 영상에 약 3분이 걸리니, 스틸로 먼저 잡는 편이 싸다.
- 겹침: 큰 번호와 제목, 도장과 칩, 아이콘과 카드
- 글자 잘림
- 빈 카드가 일찍 나오는지(접두어가 엉뚱한 단어에 걸린 경우)
- 자막 위치
- 첫 프레임에 내용이 보이는지
- 맨 마지막 프레임이 첫 프레임과 같은지(루프)

통과하면 렌더링한다.
```bash
node $SK/scripts/render.js $W/index.html video $W/silent.mp4      # 백그라운드로 실행 (90초 ≈ 3분)
```

## 6. 배경음 · 효과음 · 합성 (렌더링과 병렬)

```bash
T=$(python3 -c "import json;print(json.load(open('$W/meta.json'))['T'])")
python3 $SK/scripts/bgm.py --out $W/bgm.wav --length $T --loop           # 스타일 자동 선택(최근 3개 제외), 조성·템포·멜로디 랜덤
python3 $SK/scripts/sfx.py --meta $W/meta.json --out $W/sfx.wav
python3 $SK/scripts/mix.py --work $W --video $W/silent.mp4 --bgm $W/bgm.wav --sfx $W/sfx.wav --out $W/<제목>.mp4
```

배경음:
- 경쾌한 스타일 6개: `sunny_pop`, `drive`, `funky`, `house`, `ukulele`, `tropical`. `--list`로 설명을 볼 수 있다.
- 같은 스타일이라도 seed마다 조성, 템포(±3), 멜로디, 드럼 변형이 달라져 매번 다른 곡이 된다.
- 소재 분위기에 맞춰 고른다.
  - 정책·뉴스: `drive`, `house`
  - 생활 사례: `sunny_pop`, `ukulele`
  - 가벼운 정리: `funky`, `tropical`
- 주제가 크게 바뀌는 지점이 있으면 2곡 메들리로 만든다(1.5초 크로스페이드). 예: `--style sunny_pop,drive --switch-at <장면 시작 초>`
- `--loop`는 끝 페이드를 짧게 해서 루프 이음새가 덜 튀게 한다.

합성 레벨: 나레이션 -16 LUFS, 배경음 -26 LUFS(음성이 나올 때 자동으로 작아짐), 효과음 -13dB.
- 사용자가 음악이나 효과음이 크거나 작다고 하면 `--bgm-lufs`·`--sfx-db`만 바꿔 `mix.py`를 다시 돌린다. 재렌더링은 필요 없다.
- 결과가 30MB를 넘으면 `-crf 22`로 다시 인코딩한다.

## 7. 최종 검증 → 전달

- `ffmpeg -ss <t> -frames:v 1`로 다음 프레임을 뽑아 확인한다.
  - 첫 프레임
  - 전환 중간 2~3곳
  - 숫자나 강조가 나오는 장면
  - CTA 장면
  - 마지막 프레임(`-sseof -0.04`)
- 썸네일: 제목·인물·핵심 문구가 모두 보이는 시점의 프레임을 뽑는다(대개 3~6초).
- `SendUserFile`로 MP4와 썸네일을 보낸다. md 문서도 함께 보낸다(`display:'attach'`). 저장소에만 두면 사용자가 받을 방법을 모른다.

보고에 담을 것:
- 길이
- 장면 구성 요약
- 쓴 음성·모델
- 배경음 스타일과 seed: 같은 곡을 다시 만들 때 필요하다
- 크레딧(음성·받아쓰기)
- 확인한 것과 확인하지 못한 것: 소리는 직접 들을 수 없으니 음량 수치만 확인했다고 밝힌다
- 소재에 없는데 넣은 내용

## 8. 유튜브 메타데이터 + 은근한 CTA

`references/youtube-cta.md`를 읽고 `$W/youtube_meta.md`를 만든다. 내용은 제목 3안(추천 표시), 설명, 챕터, 출처, 고지, 해시태그, 태그, 고정 댓글 문안이다.
영상 안의 CTA는 기본으로 세 가지를 넣는다. 모두 '요청'이 아니라 시청자에게 '쓸모'로 읽히게 만든 것이다.
1. 루프 엔딩: 엔진 기본값(`CONFIG.loop`)
2. 다시 볼 만한 장면(시행일표·체크리스트)에 저장 칩
3. 맺음 장면의 질문 카드

## 수정 요청 대응

| 요청 | 다시 할 단계 |
|---|---|
| 배치·디자인·전환·타이밍 | 3 → 5 → 6의 `mix.py` (음성은 그대로) |
| 특정 장면 대본 | 그 장면만 4(생성·받아쓰기) → `prep_audio.py` → 5 → 6 |
| 음악·효과음 음량 | `mix.py`만 |
| 다른 배경음 | `bgm.py`(다른 style/seed) → `mix.py` |
| 메타데이터 | 8만 |
